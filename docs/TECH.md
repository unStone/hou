# 《厚》技术方案（初稿）

状态：2026-11-03 初稿；2026-11-09 按场景问答确定的规则更新。产品需求见 [PRD.md](PRD.md)。

## 原则

- **先跑通本地全流程**：所有数据存在本机，不做账号和同步。数据结构按"以后能同步"来设计（全局唯一编号、更新时间、删除标记），但现在不实现同步。
- **核心逻辑放在独立的包里**：格式、模型接入、考察判断计划都不依赖 Electron，可以单独测试，以后也能搬到服务器或其他端。
- **模型调用只在主进程**：密钥不进入界面进程。

## 技术栈

| 项目 | 决定 |
|---|---|
| 桌面外壳 | Electron（2026-11-03 确定）：菜单栏图标、系统通知、全局快捷键、定时任务都有成熟接口 |
| 语言 | TypeScript；包内源码直接由 Node 22.18+ 运行，不需要编译 |
| 仓库 | pnpm monorepo |
| 界面 | 沿用 `DESIGN.md` 与 `tokens.css`；界面框架在开始写桌面应用时确定（建议 React + Vite，生态最大，Electron 模板最多） |
| 本地数据库 | SQLite（better-sqlite3），一个文件 |
| 密钥 | Electron `safeStorage` 加密后存储，底层使用 macOS 钥匙串 |
| 测试 | 各包用 `node --test`；桌面应用的端到端测试以后用 Playwright 驱动 Electron |

## 包划分

| 包 | 职责 | 状态 |
|---|---|---|
| `packages/doc` | 统一阅读格式：规范、校验、原文定位、各来源转换为统一格式 | 已建：格式、校验、定位、HTML/正文/Markdown 转换 |
| `packages/llm` | 模型接入：统一的调用接口，适配不同的模型服务；支持文字、图片输入和 JSON 输出 | 已建：Anthropic、OpenAI 兼容接口 |
| `packages/core` | 《厚》的业务逻辑：提取知识点、生成考察题、判分、计划、问 AI 的提示词与流程，考察题格式校验 | 待建 |
| `apps/desktop` | Electron 应用：主进程（数据库、文件、模型调用、菜单栏、通知、快捷键、定时）与界面 | 待建 |

依赖方向：`apps/desktop` → `packages/core` → `packages/doc`、`packages/llm`。下层不依赖上层。

## 进程划分

| 进程 | 做什么 |
|---|---|
| 主进程 | 读写资料库和数据库；调用模型；导入与转换（含后台任务队列）；菜单栏、通知、全局快捷键；按计划定时触发考察 |
| 预加载脚本 | 通过 `contextBridge` 暴露一组有类型的接口给界面，界面不能直接访问 Node 和文件系统 |
| 界面进程 | 今天页、内容库、阅读器、考察窗口、设置；考察窗口是独立的 `BrowserWindow` |

## 后台运行与定时

- 关闭主窗口只隐藏窗口，应用不退出；菜单栏图标（`Tray`）常驻，菜单中有"打开《厚》"和"退出《厚》"。macOS 程序坞图标随主窗口显示或隐藏。
- 默认开机自启，用 `app.setLoginItemSettings` 设置，开机时只显示菜单栏图标；设置中可关闭。
- 定时：主进程每分钟检查一次到期的知识点，并监听 `powerMonitor` 的 `resume` 事件；休眠醒来或开机后只汇总通知一次，再按积压规则排队。
- 后台任务队列（存在数据库中，重启后继续）：知识点提取的自动重试、PDF 按章 OCR 转换。重试间隔逐次拉长，例如 1、5、15、60 分钟。

## 本地数据

位置：`~/Library/Application Support/Hou/`

```
Hou/
  hou.db                     SQLite：读物、高亮、知识点、考察、作答、判断、计划、问答、运行记录、设置
  library/<读物编号>/
    doc.json                 统一阅读格式（见 packages/doc/SPEC.md）
    original.*               原始文件或网页快照
    assets/                  图片
```

数据库表（第一版）：

| 表 | 内容 |
|---|---|
| `books` | 读物：类型（书/文章）、状态（在读/读完/未读完）、是否内置引导、来源链接或文件指纹（用于重复导入提示）、阅读目标与历史、放弃理由、读薄观点、阅读位置 |
| `chapters` | 章节：读物、在文档中的章节编号、分组标题、阅读状态（未读/已读/跳过）、提取状态（未提取/提取中/待重试/已提取）、PDF 转换状态 |
| `marks` | 高亮与批注：读物、原文位置（块编号 + 字符位置 + 原文片段） |
| `asks` | 问 AI：原文位置、一串问答（全部保留，可继续追问）、哪条存为了批注 |
| `knowledge_points` | 知识点：读物、章节、原文位置、相关程度、掌握档位、是否已掌握（含 21 天连续答对次数）、是否已移除、来源标记（高亮过/问过） |
| `assessments` | 一次考察：读物、触发原因、状态（待完成/作答中/待判断/已完成/已废弃）、考察题 JSON、题目生成时间（超过 24 小时未完成则废弃） |
| `assessment_points` | 一次考察包含哪些知识点（每次最多 3 个） |
| `answers` | 作答：每道题的作答与用时 |
| `judgments` | 判断：每个知识点的掌握程度、误解、评分理由、用户异议与最终结论 |
| `plans` | 计划：每个知识点的下次考察时间、当前间隔档（1/3/7/21 天）与理由 |
| `runs` | 运行记录：每次模型调用的输入、输出、模型、用时、组件版本 |
| `jobs` | 后台任务：类型（提取重试/PDF 转换）、对象、状态、重试次数、下次执行时间、错误 |
| `providers` | 模型服务：类型、地址、模型名、是否测试通过；密钥单独加密存储 |
| `settings` | 设置：对话与 OCR 各用哪个模型服务、旧书复习、开机自启、快捷键 |

每张表都有 `id`（UUID）、`created_at`、`updated_at`、`deleted_at`，为以后同步做准备。

## 模型接入

- 由 `packages/llm` 提供统一接口：输入为系统提示、消息（文字和图片）、可选的 JSON Schema；输出为文字、解析后的 JSON、用量。
- 第一版两种接入方式：
  - **Anthropic**：使用官方 SDK。
  - **OpenAI 兼容接口**：覆盖大部分云端服务和本机运行的模型（vLLM、Ollama、LM Studio 等），OCR 小模型也走这条路。
- 设置里可以配置多个模型服务，每个可以"测试连接"；按两种用途各指定一个：对话（提取、出题、判断、写计划理由、问 AI）和 OCR。
- 每次调用都写入运行记录。

## 导入与转换

| 来源 | 流程 |
|---|---|
| 粘贴正文 | `textToDocument` |
| Markdown（含首次使用引导） | `markdownToDocument` |
| 网页 | 主进程取网页 → defuddle 提取正文（Readability 兜底）→ `htmlToBlocks` |
| 微信公众号 | 取 `#js_content` → 下载图片 → `htmlToBlocks` |
| EPUB | 解压，按目录逐章 → `htmlToBlocks` |
| PDF | pdf.js 读取目录划分章节（没有目录时由用户按页码划分）→ 先转换前两章，其余进入后台任务队列 → 每页渲染成图片 → OCR 模型输出 Markdown → `markdownToBlocks`；页眉页脚和页码在合并时清理；失败的页可重试，重启后从断点继续 |
| X | FxTwitter 接口 → 拼接为内容块 |

## 考察、判断与计划

规则见产品方案"考察、判断与计划的规则"。在 `packages/core` 中的分工：

| 部分 | 实现 |
|---|---|
| 分组与积压 | 本地规则：同书到期知识点合并（每次最多 3 个），待完成最多 3 次，每天最多新增 3 次 |
| 出题 | 点开后调用模型；输入知识点、原文片段、当前档位与历次作答、时长预算、阅读目标；输出考察题 JSON，校验不通过重新生成一次 |
| 判断 | 本地先核对选择题和判断题的对错，再连同全部作答交给模型；模型输出每个知识点的档位（1–5）、误解和理由 |
| 计划 | 本地固定间隔（首次当天 20:00 或次日 09:30；之后 1/3/7/21 天，误解或降档回到 1 天；已掌握后 180 天抽查）；模型只生成理由，生成失败时用默认理由，不影响排期 |


- 考察生成器输出考察题 JSON，四种固定题型（情境选择、判断并说明理由、用自己的话解释、情境应用），格式在 `packages/core` 中定义并校验。
- 选择题和判断题的对错在本地判分；理由、解释、应用由模型按评分细则判分。
- 考察窗口按题型渲染固定组件，不运行模型生成的代码。
